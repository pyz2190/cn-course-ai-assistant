# D-007｜模型微调与部署可行性分析

> 版本：v1.0
> 调研日期：2026-08-16
> 范围：Embedding、Reranker、RAG/LoRA 边界；本地 GPU、云端 API、校内 AI 平台
> 本轮不实施 LoRA 训练，不承诺校内平台能力。

## 1. 模型选型

### 1.1 Embedding

主选 `BAAI/bge-m3`。官方模型卡给出 1024 维、最大 8192 token、多语言，以及 dense/sparse/multi-vector 能力；对中英双语课程资料有明确适配基础。[MD-E1]

本项目当前只接 dense 向量，使用 `FlagEmbedding==1.4.0` 的懒加载适配器；默认 CI 不安装模型可选依赖、不下载权重。正式启用前应使用 B 的真实课程语料和 C 的评测集比较召回率、延迟、内存与缓存占用，不能把模型卡结论当作本项目实测。

### 1.2 Reranker

主选 `BAAI/bge-reranker-v2-m3`。官方模型卡将其描述为多语言 reranker，直接以 query-passage 输入输出相关性分数，适合作为向量初召回后的精排。[MD-R1]

当前默认离线重排器使用确定性词项重叠，只用于开发、演示和无网络测试，不等同于正式模型质量。正式模型不可用时，系统返回未重排初检结果并明确记录降级状态。

### 1.3 替换条件

- 中英文检索质量或课程术语召回未达到 C 的评测目标时，比较其他多语言 Embedding。
- 本地资源不足时，将 Embedding/Reranker 作为校内或云端服务，但保持相同端口。
- 任何替换都必须重新建立索引，并记录模型 ID、语料指纹、top_k、评测结果与成本。

## 2. RAG 与 LoRA 的适用边界

RAG 将外部非参数知识在查询时取回并提供给生成模型；LoRA 冻结预训练权重，在层内加入可训练低秩矩阵以降低任务适配成本。[MD-RAG1][MD-LORA1][MD-LORA2]

| 需求 | 优先 RAG | 可考虑 LoRA | 理由 |
|---|---:|---:|---|
| 课程文件中的事实、定义、协议细节 | 是 | 否 | 需要随资料更新并给出来源 |
| 页码、章节、实验步骤引用 | 是 | 否 | 参数微调无法提供可靠的文档定位 |
| 最新课件、勘误、课程专属内容 | 是 | 否 | 更新索引比重新训练更直接 |
| 固定回答语气和教学话术 | 可配合 | 是 | 属于稳定行为风格，而非事实存储 |
| 固定 JSON/表格/反馈格式 | 可配合 | 是 | 可通过 prompt/schema 先解决，量大且稳定时再评估微调 |
| 课程术语表达适配 | 先 RAG/词表 | 可考虑 | 需证明检索与 prompt 不足后再训练 |
| 消除幻觉 | 必须有证据链 | 不能单独保证 | LoRA 不自动保证事实正确或引用可追溯 |

本项目结论：先完成可核验 RAG；只有积累足够、合规、去隐私、人工审核的教学话术/格式训练集，且 prompt 方案不能满足时，才立项 LoRA。即使实施 LoRA，事实问答仍保留 RAG 与 Citation 验证。

## 3. 三种部署方式对比

| 维度 | 本地 GPU | 云端 API | 校内 AI 平台 |
|---|---|---|---|
| 隐私 | 原始资料和问题可留在本地/校内设备，控制力高；仍需日志和磁盘权限治理 | 资料/问题会离开本地边界，必须核查服务条款、区域、留存与训练政策 | 理论上可在学校治理边界内；实际数据流和日志政策未知，需校方确认 |
| 成本 | 前期硬件与显存投入，空闲资源利用率风险；长期高频调用边际成本可控 | 按 token/调用计费，无硬件投入；高频或长上下文成本随量增长 | 账号、配额、计费、GPU 排队与使用范围未知 |
| 算力 | 受本机 GPU/内存限制；模型量化、批次与并发需实测 | 可选择更强模型与弹性服务，受配额和速率限制 | 可用模型、GPU、并发、上下文长度未知 |
| 维护难度 | 需维护驱动、CUDA、权重、推理服务、监控和升级 | 主要维护 API、超时、重试、配额和供应商变化 | 取决于平台是否提供兼容 API、运维 SLA 和技术支持，当前无法判断 |
| 可用性 | 离线可用，但单机故障风险高 | 依赖网络与供应商 SLA | 依赖校内网络、账号和平台 SLA，当前未知 |
| 适合阶段 | 隐私敏感、已有 GPU、可承担模型运维 | 原型与低运维启动、需要高质量生成 | 学校完成能力与合规核验后的候选方案 |

## 4. 推荐部署组合

### 当前 Demo

- Qdrant 内存模式。
- `offline-hash-v1-384d` + `offline-overlap-v1` + `offline-extractive-v1`。
- 无密钥、无网络、无付费调用即可索引、问答、引用、测试和评测 dry-run。

### 有网络的演示增强

- 仍使用本地 Qdrant 和服务端 CitationAssembler。
- 可选择 OpenAI-compatible Chat Completions 服务；密钥仅通过 `CN_AI_MODEL_API_KEY` 注入。
- connect/read/write/pool 超时分别为 3/30/10/3 秒，最多重试 1 次；失败回退离线抽取。

### 后续正式试点

- 先用 B/C 的真实、获批课程资料建立评测基线。
- 根据隐私评审选择本地 GPU、合规云 API 或经确认的校内平台。
- BGE 模型的显存、吞吐和延迟与精度、量化、batch、硬件相关，部署前必须实测，不在本报告中给出未经验证的固定显存结论。

## 5. 校内平台待确认清单

当前没有资料能够证明同济 Canvas 或校内 AI 平台已经提供可用的模型/RAG API，因此下列均是接入前提而非现成功能：

- 模型清单、版本、上下文长度、Embedding/Reranker 能力。
- API 协议、鉴权、账号角色、课程隔离和访问审计。
- 数据是否留存、是否用于训练、存储区域与删除机制。
- GPU/调用配额、并发、限流、计费、SLA 和故障支持。
- 能否访问课程文件、页面、作业、题库、讨论和字幕，以及相应授权。

## 6. 风险与控制

- **资料泄露**：只向外部生成器发送问题与取回证据，不发送 user ID、标准答案或 API Key 正文。
- **供应商不可用**：有限超时/重试，失败后离线降级；不得无限等待。
- **模型输出伪造引用**：模型只返回 evidence ID；资源、章节、页码由服务器从本次检索结果回填。
- **微调污染**：没有经过授权、去隐私和人工审核的数据不得用于 LoRA。
- **效果误判**：官方模型卡结论、分析推断和本项目实测在文档中分别标记。
