# D-002 Canvas / 学校平台 AI 能力调研

> 文档编号：D-002
> 版本：v1.0
> 调研日期：2026-08-30
> 调研对象：同济大学 Canvas 教学平台 <https://canvas.tongji.edu.cn/>
> 结论：本校部署当前未向课程成员开放任何 AI 能力，也未开放 API / LTI / 课程资源导出；
> 因此本项目按独立系统建设，Canvas 接入以适配器形式预留。

---

## 一、结论摘要

| PDF 核心要求 1 的子问题 | 结论 | 依据 |
|---|---|---|
| Canvas 中是否已有 AI、智能助教、课程问答、学习分析或类似功能 | **没有** | 团队以课程成员身份实地查看，未发现任何相关入口 |

## 二、调研方法与证据边界

### 2.1 调研方式

团队以《计算机网络》课程成员的普通账号登录本校 Canvas，逐项查看课程首页、
文件、页面、作业、测验、讨论、公告与"设置"可见项，检索是否存在
AI 助教、智能问答、学习分析、外部工具（External Apps）或课程导出入口。

### 2.2 这份结论覆盖什么、不覆盖什么

这一区分直接决定后续能不能改变结论，必须写清楚：

- **本文结论描述的是"本校该部署在课程成员权限下开放了什么"**，
  是一个有时间戳的观察结果，不是对 Canvas 这一产品的通用能力判断。
- Canvas 作为商业产品，其公开文档一直包含 REST API、LTI 与课程导出（Course Export）能力。
  本文结论为"否"，指的是**这些能力在本校部署中未向本团队开放、也未取得申请通道**，
  而不是"Canvas 不具备这些能力"。对外汇报时不能把两者混为一谈。
- 团队没有课程管理员、账号管理员或学校信息化部门权限，
  因此**无法排除**这些能力在管理员层面已经启用、只是不对课程成员可见的可能性。
- 结论的有效期截至调研日期。第六节列出了需要重新调研的触发条件。

### 2.3 未取得的材料

以下材料在本轮调研中未能取得，相关判断因此只作为前提而非事实陈述：

- 本校 Canvas 的版本号与已启用的功能开关清单
- 管理员层面的 External Apps / Developer Keys 配置
- 学校对课程数据导出、外部系统对接的审批流程与合规要求
- 校内是否另有独立于 Canvas 的 AI 平台及其接入条件

## 三、逐项调研结果

### 3.1 是否已有 AI、智能助教、课程问答或学习分析功能

**结论：没有。**

课程成员视角下未见任何 AI 助教、智能问答、自动答疑、智能出题或
学习分析报告类入口。课程内的交互仍以公告、讨论区和作业反馈为主，
答疑依赖教师与助教的人工响应。

由此产生的直接后果是：**课程问答目前没有任何自动化承载**，
学生的重复性问题（概念辨析、实验环境、工具用法）全部占用助教的人工时间。
这正是本项目要解决的问题，也是本项目独立建设的现实理由。

### 3.2 AI 能否接入课程文件、页面、作业、题库、讨论、视频字幕

**结论：不能。**

因为平台侧不存在可用的 AI 组件（见 3.1），"AI 接入课程资源"这一问题在当前部署下不成立。
需要强调的是，**课程资源本身是存在的**——课件、实验指导、作业与讨论都在 Canvas 中，
缺的是把这些资源喂给 AI 的通道，而不是资源本身。

这意味着：只要将来打通了资源侧的读取通道，本项目的知识库可以直接受益，
不需要重建内容。第四节的接口需求正是围绕这一点提出的。

### 3.3 是否支持 API 集成、外部工具接入、LTI、课程资源导出

**结论：否（在本团队可见与可申请的范围内）。**

| 能力 | 课程成员视角观察 | 对本项目的影响 |
|---|---|---|
| REST API 集成 | 未见开放入口，团队无 access token 或申请通道 | 无法自动拉取课程文件与元数据 |
| 外部工具接入 / LTI | 课程内未见 External Apps 配置入口 | 本系统无法作为课程内的工具嵌入，学生需另行访问 |
| 课程资源导出 | 未见课程导出（Course Export）入口 | 无法批量获得课程包，资料只能逐份人工下载 |

三项均为否，其共同后果是：**本项目在资料获取环节没有任何自动化通道**，
课程资料必须由教师或助教人工下载后，通过本系统的
`POST /api/v1/resources/upload` 上传。这正是当前系统采用文件上传作为唯一资料入口的原因。

## 四、需要补哪些接口或外部系统能力

这是本次调研的落点。能力按"由谁提供"分为两层。

### 4.1 需要学校 / 平台侧开通的能力

以下能力本项目无法自建，必须由学校信息化部门或课程管理员开通。
每项都注明：没有它时本项目怎么办（降级方案），以及拿到它之后能改善什么。

| # | 需要开通的能力 | 用途 | 没有它的降级方案（当前做法） | 开通后的收益 |
|---|---|---|---|---|
| P1 | Canvas REST API 只读凭据（课程范围） | 自动同步课程文件、页面、作业与公告 | 教师人工下载后经 `/resources/upload` 上传 | 资料更新自动化，消除人工搬运与版本滞后 |
| P2 | 课程资源导出（Course Export / IMSCC 包） | 一次性获得课程完整资料包做冷启动 | 逐份人工下载，覆盖面依赖人工判断 | 冷启动一次到位，知识库覆盖面可核对 |
| P3 | LTI 1.3 外部工具注册 | 把助教嵌入课程内，复用课程身份 | 学生另行访问独立站点，本系统自行标识用户 | 免二次登录，学习行为可归属到真实课程成员 |
| P4 | 视频字幕（Caption）获取通道 | 把课程录像转为可检索、可引用的文本 | 无；当前缺少字幕类语料（见 D-003 第七节） | 补上课堂讲解这一最贴近教学口径的语料 |
| P5 | 题库 / 测验（Quizzes）读取 | 让任务的完成判据复用课程既有试题 | 由课程组自编试题（见 `/exercises` 接口） | 试题与课程考核口径统一 |
| P6 | 讨论区（Discussions）读取 | 从真实提问中挖掘高频问题，反哺问答库 | 由课程组凭经验拟题 | 问答库选题从真实需求出发，而非主观判断 |
| P7 | 数据合规与授权口径 | 明确哪些资料可入库、可否落盘、可否外发 | 默认最小化：只用课程组明确授权的资料 | 消除合规不确定性，才敢接入云端模型 |

**优先级建议：** P1 与 P2 收益最高且技术风险最低（只读、单向、可离线验证），应优先申请；
P3 涉及身份与权限，审批链条最长，建议在 P1/P2 落地并跑通后再提；
P4–P6 属于内容增量，可随课程建设逐步推进；P7 应与 P1 同时提出，否则拿到接口也不敢用。

### 4.2 因平台不开放而必须由本项目自建的能力

以下能力原本可以由平台提供，因 3.3 全否，本项目已自行实现：

| 平台缺失的能力 | 本项目的替代实现 | 代码位置 |
|---|---|---|
| 课程资料自动同步 | 文件上传 + 自动解析切块入库 | `POST /api/v1/resources/upload` |
| 课程资料元数据登记 | 资料导入契约 | `POST /api/v1/resources/import` |
| 课程问答 | 基于 RAG 的带引用问答 | `POST /api/v1/qa/ask`，见 D-004 |
| 知识点组织 | 知识图谱与先修关系 | `GET /api/v1/knowledge-points` |
| 题库 | 课程试题与任务关联 | `GET /api/v1/exercises` |
| 教学任务发布 | 六类任务引擎 | `/api/v1/tasks`，见 D-008 |
| 学习行为记录 | 独立系统内部事件 | `/api/v1/events` |
| 回答质量的人工闭环 | 反馈审核 → 知识库变更任务 | `/api/v1/feedback`、`/api/v1/knowledge-base/changes` |

字段级的接口需求与请求响应定义见 [D-009 接口需求说明](D-009-接口需求说明.md)。

### 4.3 两条落地路径

**路径 A：学校开通 P1/P2（推荐）**

在 `apps/api/app/adapters/` 下新增 Canvas 适配器，实现现有的
`FileResourceImporter` 端口，把 Canvas 的文件与元数据转换为 `ChunkMetadata`。
领域模型、问答链路、任务引擎与前端**均不需要改动**——这正是当前端口化设计的目的。

**路径 B：学校不开通（当前状态）**

维持人工上传。此路径下本项目功能完整、可独立运行，
代价是资料更新依赖人工节奏，以及无法获得字幕、题库与讨论区语料。
D-003 第七节记录了这一代价造成的实际语料缺口。

**关键判断：** 两条路径的差异只在资料入口，不在系统架构。
因此不必等待学校审批结果再开工，这也是本项目当前的实际推进方式。

## 五、对项目边界的影响

`spec.md`、`docs/architecture.md` 与 `README.md` 中"不接入 Canvas API、LTI、
课程身份、资源同步、成绩回写"的表述，是**本次调研的结论**，而不是随意设定的假设。
本文档为那些边界声明补上了依据。

系统同时保证：不把未取得的能力描述成已实现的功能，不在领域模型和前端中
泄漏 Canvas 专有字段，使将来接入时无需重构。

## 六、复核方式与失效条件

本文结论有明确的失效条件。出现以下任一情况时，必须重新执行本调研并更新本文档：

1. 学校发布 Canvas 版本升级或新功能公告，涉及 AI、外部工具或数据接口。
2. 团队取得课程管理员或更高权限，可以查看 External Apps 与 Developer Keys。
3. 学校信息化部门对第四节任一项申请给出答复。
4. 校内上线独立于 Canvas 的 AI 平台。
5. 距本次调研超过一个学期。

复核时应重新执行 2.1 的查看步骤，并在本文档追加带日期的修订记录，
而不是直接覆盖原结论——结论的变化过程本身是有价值的记录。
