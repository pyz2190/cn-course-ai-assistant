# 五人分工与交付边界

| 角色 | 主责 | 主要目录 | 首批交付 |
|---|---|---|---|
| A | 平台、集成、基线与总协调 | 根配置、`core/`、CI、文档 | 仓库骨架、统一配置、接口基线、联调机制 |
| B | 知识库与课程语料 | 资源导入适配器、元数据处理 | 资料清单、切分规则、可追溯语料 |
| C | 问答评测与质量保障 | `tests/`、评测脚本 | 评测集、评分规则、回归报告 |
| D | RAG、模型与问答后端 | 检索和生成适配器、`services/qa.py` | 检索链路、回答生成、引用与降级 |
| E | 教学任务与产品前端 | `apps/web/`、任务与事件接口 | 六类任务、学生工作台、学习事件 |

## A：平台与集成

- 维护跨模块契约、环境配置、错误格式和 CI。
- 组织接口评审和集成验收。
- 调研 Canvas 能力；没有可靠证据时保持适配器边界，不把未知能力写成已实现功能。

## B：知识库与语料

- 维护课程资料来源、授权、版本、章节、页码和视频时间码。
- 输出统一 `ChunkMetadata`。
- 保证每个检索片段能追溯到课程原始材料。

## C：评测与测试

- 按定义、机制、计算、实验、排错、应用六类问题构建评测集。
- 维护正确性、相关性、引用、完整性和安全性评分。
- 对契约和核心用户路径建立回归测试。

## D：RAG 与模型

- 实现 `Retriever` 与 `AnswerGenerator` 端口。
- 处理无结果、低置信度、模型不可用和超时。
- 只基于允许访问的课程资料回答，并返回引用。

## E：教学任务与前端

- 实现概念解释、分层讲解、例题、实验、诊断、复习六类任务。
- 维护加载、空状态、失败和降级交互。
- 通过 `LearningEvent` 记录可供分析的关键行为。

跨角色改动以契约为连接点。任何成员都可以改进公共模块，但必须邀请对应负责人评审。
