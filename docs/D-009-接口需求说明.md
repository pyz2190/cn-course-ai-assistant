## 一、本文的定位

README 的"接口一览"是**已实现接口的清单**，面向使用者。
本文是**接口需求说明**，面向两类读者：

1. **学校信息化部门 / 课程管理员**：第三节列出本项目需要平台提供什么，
   以及为什么需要——这部分接口**尚未取得**，是需求而非现状。
2. **系统对接方与前端开发者**：第四至七节给出已实现接口的字段级定义、
   约束、错误行为与降级表现。

两部分的区别必须清楚：**第三节全是待申请项，第四至七节全是已实现项。**

## 三、Canvas / 学习平台 API 需求（待申请）

依据：[D-002](D-002-Canvas平台AI能力调研.md) 的调研结论——本校 Canvas 部署
未向课程成员开放 API、LTI 与课程导出。本节把 D-002 第 4.1 节的能力需求
落到具体的接口粒度，供向学校提出申请时使用。

**统一原则：全部只读、单向拉取。本项目不请求任何写入权限，
不回写成绩、不回写学习行为、不修改课程内容。** 这既降低审批难度，
也符合 `spec.md` 的项目边界。

### 3.1 认证与授权

| 项目 | 需求 |
|---|---|
| 方式 | OAuth 2.0 授权码模式，或课程范围的只读 access token |
| 权限范围 | 单一课程的只读范围；不需要账号级或全站权限 |
| 令牌生命周期 | 需明确有效期与刷新方式，以便设计续期逻辑 |
| 存储 | 令牌以 `SecretStr` 保存，仅存于环境变量，不写入仓库与日志 |
| 降级 | 无令牌时系统正常运行，资料入口退化为人工上传 |

若采用 **LTI 1.3**（对应 D-002 的 P3），额外需要：
平台注册信息（issuer、client_id、deployment_id）、JWKS 端点、
OIDC 登录与重定向地址，以及 Names and Role Provisioning Service 的开通说明。

### 3.2 需要的资源端点

下表的"期望字段"是本项目**实际会用到**的最小字段集，
不是要求平台提供全部数据。"映射到"列说明该字段进入本系统后落到哪个模型，
使申请方能看清数据用途。

| 端点用途 | 期望字段 | 映射到本系统 | 优先级 | 缺失时的降级 |
|---|---|---|---|---|
| **课程文件列表与下载** | 文件 ID、文件名、MIME 类型、大小、更新时间、下载地址 | `ChunkMetadata.source_url` / `title` / `updated_at` | **P1** | 人工下载后 `/resources/upload` |
| **课程页面** | 页面标题、正文 HTML、更新时间 | `ChunkMetadata.content` / `chapter` | P2 | 人工复制为文本上传 |
| **作业** | 标题、说明正文、截止时间、关联模块 | `TaskTemplate.description` / `completion_criteria` | P2 | 课程组人工录入任务 |
| **测验 / 题库** | 题干、题型、选项、正确答案、解析、关联知识点 | `Exercise` 全部字段 | P2 | 课程组自编试题 |
| **讨论区** | 主题标题、正文、回复、时间 | 问答库选题输入（不直接入库） | P3 | 凭教学经验拟题 |
| **视频字幕** | 字幕文本、时间轴、语言 | `ChunkMetadata`（`content_type=subtitle`） | **P1** | 无替代，语料缺口 |
| **课程导出包** | IMSCC / Common Cartridge 归档 | 冷启动批量导入 | **P1** | 逐份人工下载 |

**为什么字幕是 P1：** 它是唯一记录课堂实际讲解口径的语料，
无法由教材或课件替代；D-003 第 7.4 节实测的语料缺口中它占比最高。

### 3.3 导出格式要求

| 项目 | 需求 |
|---|---|
| 优先格式 | IMSCC / Common Cartridge（含资源与结构） |
| 可接受格式 | 原始文件打包 + 独立的元数据清单（CSV / JSON） |
| 必需元数据 | 资料标题、类型、语言、版本或更新时间、所属模块或章节 |
| 字幕格式 | SRT 或 WebVTT（系统已支持解析这两种） |
| 编码 | UTF-8 |

**元数据是硬要求，不是可选项。** 没有章节归属的资料无法通过
D-003 的 S4 切块判据（`chapter` 必填），只能人工补录，
批量导入的意义会大打折扣。

### 3.4 权限、配额与稳定性

向平台方申请时需一并确认，否则无法设计同步策略：

| 项目 | 需要确认 | 影响 |
|---|---|---|
| 速率限制 | 每分钟 / 每小时的请求上限 | 决定同步批量与退避策略 |
| 分页 | 分页方式与单页上限 | 决定拉取循环的实现 |
| 增量同步 | 是否支持按更新时间过滤 | 无此能力则每次全量拉取，代价高 |
| 大文件 | 单文件大小上限与超时 | 决定下载的分块与重试 |
| 可用窗口 | 是否有维护窗口 | 决定同步任务的调度时间 |
| 数据合规 | 哪些数据可落盘、可否提供给外部模型 | **决定能否使用云端模型**，见 D-007 |

### 3.5 接入后的改动范围

一旦上述接口可用，本项目的改动被限制在适配器层：

1. 在 `apps/api/app/adapters/` 新增 Canvas 适配器，实现现有的
   `FileResourceImporter` 端口
2. 把 Canvas 字段转换为 `ChunkMetadata` 与 `ResourceImportRequest`
3. **领域模型、问答链路、任务引擎与前端不改动**

**Canvas 专有字段不得进入领域模型和前端**，必须在适配器内完成转换。
这是当前端口化设计的目的，也是接入时的验收标准。

## 四、资料导入接口（已实现）

### 4.1 `POST /api/v1/resources/import` — 元数据登记

只登记资料元数据，不上传文件内容。用于外部系统告知"有这样一份资料"。

**请求 `ResourceImportRequest`：**

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `course_id` | string | 是 | 非空 |
| `resource_type` | enum | 是 | `textbook` / `slide` / `lab_guide` / `video_subtitle` / `rfc` / `other` |
| `title` | string | 是 | 非空 |
| `version` | string | 是 | 非空 |
| `language` | enum | 是 | `zh` / `en` / `bilingual` |
| `content_type` | enum | 是 | `pdf` / `ppt` / `subtitle` / `text` / `rfc` / `table` / `formula` / `image` / `diagram` / `other` |
| `source_url` | string | 否 | 可为空 |

**响应 `ResourceImportResponse`（202）：** `resource_id`、`sync_status`
（`accepted` / `completed` / `failed`）、`metadata`（`ChunkMetadata` 或 null）、`error`。

### 4.2 `POST /api/v1/resources/upload` — 文件上传与解析

`multipart/form-data`。上传后自动解析、切块并增量写入向量库，
新资料**立即可被问答检索和引用**。

| 表单字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `file` | 是 | — | 支持 PDF、PPTX、SRT、VTT、TXT、Markdown、RFC |
| `course_id` | 是 | — | 课程标识 |
| `title` | 是 | — | 资料标题 |
| `content_type` | 是 | — | 同 4.1 的枚举 |
| `version` | 否 | `v1` | 版本号 |
| `language` | 否 | `zh` | 语言 |
| `knowledge_point_ids` | 否 | 空 | 逗号分隔 |

**响应 `ResourceUploadResponse`（201）：** `resource_id`、`filename`、
`chunk_count`、`parse_status`、`chunks[]`、`indexed_chunks`（为空表示未向量化）、`error`。

**错误：** 不支持的 `content_type` 或扩展名返回 422，响应体为第九节的统一错误结构。

### 4.3 资料查询

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/resources` | 已导入资料列表，可按 `course_id` 过滤 |
| `GET` | `/resources/{resource_id}/chunks` | 该资料解析出的全部 Chunk |

### 4.4 `ChunkMetadata` 字段约束

所有引用可追溯性的基础。**跨角色对接时以此为准：**

| 字段 | 必填 | 约束 |
|---|---|---|
| `chunk_id` / `resource_id` | 是 | 非空 |
| `knowledge_point_ids` | 是 | **至少一个**——无知识点归属的 Chunk 不得入库 |
| `title` / `content` / `chapter` | 是 | 非空；`chapter` 是引用可核对性的基础 |
| `page_start` / `page_end` | 否 | ≥ 1；提供 `page_end` 时必须提供 `page_start`；`page_end ≥ page_start` |
| `language` / `content_type` | 是 | 见 4.1 枚举 |
| `version` | 是 | 非空，用于区分同一资料的不同版次 |
| `access_level` | 是 | `public` / `course` / `private`；受版权资料必须为 `course` |
| `parse_status` | 是 | `pending` / `parsed` / `failed` |
| `updated_at` | 是 | ISO 8601 时间戳 |

## 五、问答接口（已实现）

### 5.1 `POST /api/v1/qa/ask`

**请求 `AskRequest`：**

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `course_id` | string | 是 | 非空 |
| `user_id` | string | 是 | 非空 |
| `question` | string | 是 | 1–2000 字符，**不能是纯空白** |
| `knowledge_point_ids` | string[] | 否 | 缩小检索范围 |
| `resource_ids` | string[] | 否 | 缩小检索范围 |
| `task_id` | string | 否 | 关联提问来源的任务 |

**响应 `AskResponse`：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `answer` | string | 非空 |
| `citations` | Citation[] | 见 5.2；**可能为空数组**，见 5.3 |
| `confidence` | float | 0–1 |
| `request_id` | string | 提交反馈时必须回传 |
| `degraded` | bool | 是否降级（重排或外部生成不可用） |
| `mode` | enum | `offline` / `external` |

### 5.2 `Citation` 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `citation_id` / `chunk_id` / `resource_id` | 是 | 定位标识 |
| `title` / `chapter` | 是 | 可读的资料与章节 |
| `page_start` / `page_end` | 否 | ≥ 1 |
| `quote` | 是 | 原文摘录，非空 |
| `source_url` | 否 | — |
| `retrieval_score` | 否 | −1 ～ 1 |
| `rerank_score` | 否 | 未启用重排时为空 |

**引用安全约束（对接方必须知道）：** `Citation` 的
资料名、章节、页码与摘录**全部由服务端从 `ChunkMetadata` 回填**，
不采信模型输出。模型即使虚构资源名或不存在的 ID 也无法进入最终引用。
实现见 [D-004](d-rag/D-004-rag-technical-solution.md) 第 6 节。

### 5.3 空引用是正常响应，不是错误

当课程资料中没有足够证据时，系统返回**安全拒答**：
`citations` 为空数组，`answer` 说明证据不足，HTTP 状态码仍为 200。

**前端必须把这种情况当作正常回答渲染，不能报错。**
D-003 第 7.3 节实测的 30 题中有 8 题走这条路径。

## 六、任务发布接口（已实现）

### 6.1 `POST /api/v1/tasks`

**请求 `TaskPublishRequest`：**

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `task_id` | string | 是 | 非空；重复返回 409，**不覆盖原任务** |
| `title` / `description` | string | 是 | 非空 |
| `task_type` | enum | 是 | `foundation` / `protocol_analysis` / `case_study` / `innovation_challenge` / `project_practice` / `troubleshooting` |
| `knowledge_point_ids` | string[] | 是 | **至少一个** |
| `resource_ids` | string[] | 是 | **至少一个** |
| `exercise_ids` | string[] | 否 | 关联试题，见第七节 |
| `prerequisite_ids` | string[] | 否 | 先修任务 |
| `completion_criteria` | string[] | 是 | **至少一条** |
| `ai_feedback_points` | string[] | 是 | **至少一条** |
| `status` | enum | 否 | 默认 `published`；传 `draft` 先存草稿 |

**响应：** `TaskTemplate`（201）。

四个"至少一个"的约束共同保证：**任务必然关联知识点、资料、完成判据和
AI 反馈介入点**，不存在孤立任务。

### 6.2 任务查询与状态流转

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/tasks` | 可按 `status`、`task_type` 过滤 |
| `GET` | `/tasks/{task_id}` | 任务详情；不存在返回 404 |
| `PATCH` | `/tasks/{task_id}/status` | 在 `draft` / `published` / `completed` 之间流转 |

### 6.3 学习行为事件

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/events` | 记录事件 |
| `GET` | `/events` | 按 `course_id`、`user_id`、`event_type`、`object_id` 查询 |

`LearningEvent`：`event_id`、`course_id`、`user_id`、`event_type`
（`qa_asked` / `task_opened` / `task_completed` / `feedback_submitted`）、
`object_id`、`occurred_at`、`payload`。

**事件完全由本系统承载，不回写任何外部平台。**

## 七、试题接口（已实现）

试题是任务完成判据的可判定载体，使
「任务 → 知识点 → 课程资料 → 试题 → AI 反馈」形成闭合引用链。

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/exercises` | 可按 `knowledge_point_id` 或 `task_id` 取题 |
| `GET` | `/exercises/{exercise_id}` | 试题详情；不存在返回 404 |

`task_id` 指向不存在的任务时返回 404；任务存在但未关联试题时返回空数组。

**`Exercise` 字段：**

| 字段 | 必填 | 约束 |
|---|---|---|
| `exercise_id` / `question` | 是 | 非空 |
| `exercise_type` | 是 | `single_choice` / `multiple_choice` / `short_answer` / `analysis` / `design` |
| `knowledge_point_ids` | 是 | **至少一个**——试题必须挂在知识图谱上 |
| `resource_ids` | 否 | 命题依据的课程资料 |
| `difficulty` | 是 | `introductory` / `intermediate` / `advanced` |
| `options` | 否 | 选择题**至少两项**；非选择题**必须为空** |
| `reference_answer` | 是 | 非空 |
| `explanation` | 否 | 解析 |
| `source` | 是 | `textbook` / `lab_guide` / `past_exam` / `course_team` |
| `review_status` | 是 | `draft` / `reviewed` / `approved` |

**版权提示：** `source = past_exam` 的试题受 D-003 第 2.2 节约束，
需课程组批准后方可入库。

## 八、反馈与知识库变更接口（已实现）

构成"学生反馈 → 人工审核 → 优化知识库"的闭环，制度层的责任人与
时限见 [D-003](D-003-知识库与问答库建设方案.md) 第六节。

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/feedback` | 学生提交反馈，需回传问答的 `request_id` |
| `GET` | `/feedback` | 教师与助教的待审核队列 |
| `PATCH` | `/feedback/{id}/review` | 审核；`approved` 时**必须**提供 `suggested_action` |
| `GET` | `/knowledge-base/changes` | 变更任务列表 |
| `PATCH` | `/knowledge-base/changes/{id}` | 推进或关闭；`wont_fix` **必须**填 `resolution_notes` |
| `POST` | `/quality/reviews` | 语料质量审查记录（1–5 分） |

模型层强制的三条状态约束：

1. `pending_review` 的反馈不得携带审核元数据或变更任务引用
2. 审核后 `reviewer` 与 `reviewed_at` 必填
3. 只有 `approved` 的反馈可以关联知识库变更任务

## 九、统一错误契约

所有错误响应使用同一结构 `ApiError`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | string | `validation_error` 或 `http_<状态码>` |
| `message` | string | 可展示给用户的中文说明 |
| `request_id` | string | 与 `X-Request-ID` 响应头一致 |
| `details` | object | 校验错误时包含逐字段的 `errors` 列表 |

| 状态码 | 触发条件 |
|---|---|
| 404 | 任务、试题、知识点、反馈或变更任务不存在 |
| 409 | 发布任务时 `task_id` 重复 |
| 422 | 请求不符合契约（空问题、非法页码、越界置信度、不支持的文件类型等） |

每个请求都会带回 `X-Request-ID` 响应头；未提供时由服务端生成。
**排查问题时请一并提供该值。**

## 十、接口变更流程

**先改契约，再改实现。** 修改 `apps/api/app/domain/models.py` 后必须运行：

```bash
npm run contracts     # 重新导出 OpenAPI 与 JSON Schema，并生成前端类型
```

并提交生成结果，否则 CI 的 `check:contracts` 会因契约漂移失败。
完整流程见 [接口变更流程](interface-change.md)。
