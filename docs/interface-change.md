# 接口变更流程

接口是五人并行开发的公共基线。任何影响请求、响应、枚举、错误码或事件字段的改动，都必须按本流程执行。

## 变更步骤

1. 在 Pull Request 中写清使用场景和受影响成员。
2. 先修改 `apps/api/app/domain/` 中的 Pydantic 模型或 API 路由。
3. 运行 `npm run contracts` 重新生成 OpenAPI、JSON Schema 和前端类型。
4. 同步更新 `contracts/examples/`、后端测试和前端调用。
5. 在 PR 模板的“接口变更”区列出兼容性结论和迁移方法。
6. 至少由一位受影响模块负责人评审后再合并。

## 兼容性规则

| 变更 | 兼容性 | 处理方式 |
|---|---|---|
| 新增可选字段 | 通常兼容 | 同一 `/api/v1` 内发布 |
| 新增枚举值 | 条件兼容 | 消费端必须有未知值兜底 |
| 删除或重命名字段 | 不兼容 | 先弃用，或发布新版本 |
| 修改字段类型或语义 | 不兼容 | 发布新版本并提供迁移期 |
| 新增错误码 | 兼容 | 文档化，前端保留通用错误处理 |

## 接口记录模板

```markdown
### IF-XXX 变更标题

- 发起人：
- 日期：
- 关联任务：
- 变更前：
- 变更后：
- 影响模块：
- 是否向后兼容：
- 迁移方案：
- 评审人：
```

禁止直接编辑生成的 `contracts/openapi.json`、`contracts/schemas/` 或 `apps/web/src/api/schema.d.ts`；它们必须由模型和路由生成。
